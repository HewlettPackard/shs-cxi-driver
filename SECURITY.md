# Security Policy

## Reporting a Vulnerability

Do not report security vulnerabilities in public issues, public pull requests, or open mailing lists.

Report vulnerabilities through your established HPE security reporting process:

- Internal contributors: use the internal security incident/vulnerability channel required by your organization.
- External reporters: use HPE's public vulnerability reporting channel and coordinated disclosure process.

Public HPE security contact and process information is available at:

- https://www.hpe.com/us/en/trust-center/security-vulnerability.html

Include as much detail as possible:

- Affected component(s) and file paths.
- Affected versions/branches and environment details.
- Reproduction steps and proof-of-concept details.
- Security impact assessment (confidentiality/integrity/availability).
- Any suggested mitigations.

## Response Expectations

After receiving a valid report, maintainers will:

- Acknowledge receipt.
- Triage severity and impact.
- Coordinate remediation and disclosure timing through the appropriate security process.

## Supported Versions

Security fixes are prioritized according to active support and release policies for this project and its parent product streams.
